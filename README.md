# Как работать в репозитории

Инструкция для GitHub Desktop


## 1. Один раз: скачать проект
File → Clone repository → вкладка GitHub.com → выбрать репозиторий → Clone.

## 2. Золотое правило
**Никогда не работай в ветке `main`.** Перед тем как что-то менять, смотри на кнопку Current branch: там должно быть `feature/...`.

## 3. Начало каждой задачи
1. Current branch → выбрать **main**.
2. Нажать **Fetch origin**, затем **Pull origin** (если появилась кнопка). Так ты берёшь свежую версию.
3. Current branch → **New branch**.
4. Название по шаблону `feature/что-делаю`, например `feature/sergey-select-field`. Нажать Create branch.

## 4. Работа
1. **Open in Visual Studio Code** (или Ctrl+Shift+A).
2. Меняй файлы **только в своей папке**: Алиса в `backend/`, Сергей и Рома в `frontend/` (в разных файлах).
3. Сохраняй файлы (Ctrl+S).

## 5. Коммит (сохранить точку)
1. В GitHub Desktop слева виден список изменённых файлов. Проверь, что там только нужное.
2. В поле Summary коротко напиши, что сделано:
   - `feat: поле select в форме` (новое)
   - `fix: ошибка в проверке возраста` (исправление)
   - `docs: пример схемы` (документы)
3. Нажми **Commit to feature/...**.

Делай коммиты часто: хотя бы раз в час работы.

## 6. Отправить на GitHub
Нажми **Publish branch** (в первый раз) или **Push origin** (дальше).

## 7. Pull request
1. Нажми **Create Pull Request**: откроется сайт.
2. Проверь: base = `main`, compare = твоя ветка.
3. Заполни описание по шаблону: что сделано, как проверить.
4. Справа в Reviewers выбери ревьюера (тимлида).
5. Нажми **Create pull request**.

## 8. После ревью
- Если в комментариях просят доработать: внеси изменения в **той же ветке**, коммит, Push origin. Pull request обновится сам.
- Если ревьюер нажал Approve, тимлид сливает ветку.
- После слияния: переключись на `main`, Fetch origin, Pull origin и начни следующую задачу с шага 3.

## Что делать, если...
| Ситуация | Что делать |
|---|---|
| Случайно начал работу в `main` | Не делай коммит. Создай новую ветку: изменения уйдут в неё вместе с тобой. GitHub Desktop предложит оставить их в новой ветке (Bring my changes to the new branch) |
| Нет кнопки Push | Сначала нужен хотя бы один коммит |
| GitHub Desktop пишет про конфликт | Нажми Update from main, Open in VS Code, выбери нужный вариант (Accept Current / Incoming / Both), удали маркеры `<<<<<<<`, сохрани, вернись и сделай коммит. Если запутался, позови тимлида |
| Не вижу чужие изменения | main → Fetch origin → Pull origin |
| Не знаю, какая ветка стоит | Смотри на Current branch вверху |
| Застрял больше часа | Напиши в чат команды. Это нормально |

## Что нельзя коммитить
- Пароли, ключи, файл `.env`
- Папки `node_modules`, `__pycache__`, `.venv`
- Большие файлы и архивы

Если случайно закоммитил секрет, сразу скажи тимлиду: его нужно поменять, просто удалить файл недостаточно.

## Правила команды
1. В `main` напрямую не пушим.
2. Одна задача: одна ветка, один небольшой pull request.
3. Не меняем чужие файлы без согласования.
4. JSON-контракт (`docs/`, `examples/`) меняем только через pull request и предупредив всех.
5. Ревью быстрое: тимлид смотрит pull request в течение дня.
